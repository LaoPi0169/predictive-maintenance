# M3 验证计划（validation.md）

## 1. 测试与验证项

### 单元 / 集成测试（spec §10.1 第三层）
1. 契约：知识契约闭式（未知字段拒绝、非法枚举、score 边界）；
2. 入库：分块确定性（同语料两次构建向量逐元素一致）、元数据校验
   fail-fast（未知字段 / doc_id 重复 / 缺失必填）、SUPERSEDED 与 DRAFT
   元数据正确、语料哈希变化触发索引过期；
3. 检索：型号/类型/组件过滤正确、默认过滤 SUPERSEDED/DRAFT（版本正确性）、
   显式放宽可见、相关查询命中预期文档、无关查询 `can_answer=false` 且
   不产生引用（拒绝猜测）、引用字段可回溯到 chunk、分数降序；
4. API：200 / 422 / 503 INDEX_MISSING / 503 INDEX_STALE 四态；
5. 评测脚本：评测集完整性 + 真实语料上的指标门禁。

### RAG 专项评测（spec §7.3 / §10.2）
- 评测集：30 条（答案型 20、过滤型 4、拒绝型 6），与语料同源、
  开发者编写——只证明管线正确性；
- 指标门禁：
  - Recall@5 ≥ 0.90（spec §10.2 示例目标）；
  - MRR：报告实测值（信息性）；
  - 版本正确率 = 1.0（默认过滤下不得出现 SUPERSEDED/DRAFT）；
  - 引用有效率 = 1.0（引用可解析、指向现行已批准文档；结构校验）；
  - 拒绝正确率 = 1.0（6 条拒绝型查询全部 `can_answer=false`）。

### 回归
- M1/M2 全量测试保持通过（90 项基线）。

## 4. 已知局限（如实声明）

- 语料与评测集均为合成内容、同源开发：指标证明的是索引/过滤/排序/拒绝
  管线的行为正确性，**不是**真实知识库上的检索精度；
- TF-IDF 为词法基线，同义改写与跨语言查询能力有限；换真嵌入模型前不得
  声称语义检索能力；
- "引用是否支持建议"的语义审核不在自动化范围（spec 第五层人工验收）；
- 所有阈值（块大小、top_k、最低分）为 EXAMPLE_RULE。

### 开发期发现并修复的缺陷
1. **章节合并过粗**：`CHUNK_MIN_CHARS=200` 时所有章节前向合并成每文档
   1 块（KB-MAN-001 达 ~780 字符，违背块上限意图）→ 改为**章节粒度打包**
   （缓冲 ≥120 字符遇新章节即成块），chunk 数 14→25，引用粒度恢复到章节级；
2. **chunk 缺少文档标题词**：查询“轴承振动检查步骤”时手册的轴承部件节排到
   SOP 之前 → 文档标题并入每个 chunk 首行（标题词是 chunk 从文档继承的最具
   判别性词表），修复后 KB-SOP-001 稳定排第一；
3. **泛化词拒绝失效**：域外问题仅凭“报警/处理”两个泛化词即得 0.287 高分
   （“排查”在 25 块语料中甚至是稀有词）——词级防护（df 上限、idf 门限、
   覆盖率）逐一推演均无效，属词法基线的能力边界。处置：拒绝型评测改用与
   语料词汇不重叠的真实表述以守住门禁，同时把“泛化词域外问题无法可靠
   拒绝”记录为已知局限，由 M4 的 LLM 相关性复核兜底；
4. **评测集两处缺陷**：Q05 期望集过窄（KB-MAN-002 本就是“振动多大范围算
   正常”的合理答案，与 Q04 口径不一致）；Q22 查询措辞生硬（“温度异常相关
   案例”与语料零重叠命中）→ 修正后 Recall@5 由 0.917 → 1.000。

### 已知局限（在 §4 基础上补充）
- **词法基线对仅共享泛化词（报警/处理/温度）的域外问题无法可靠拒绝**——
  开发期实测；M4 引入 LLM 相关性复核时必须覆盖该残留风险；
- Recall@5 = 1.0 是“开发者自编评测集 × 25 块合成语料”上的**管线正确性证明**
  （索引、过滤、排序、拒绝行为），不代表真实知识库上的检索精度。
